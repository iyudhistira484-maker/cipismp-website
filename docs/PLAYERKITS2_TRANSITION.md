# Transisi kit ke PlayerKits2 — NO-GO sampai diuji

**Checkout dan polling produksi tetap tertutup.** Jangan mengirim ulang comp, mengubah antrean, atau mencabut/memberi permission pada produksi tanpa rekonsiliasi dan persetujuan Owner. Merge kode atau status `DELIVERED` bukan bukti bahwa kit dapat diklaim.

## Temuan

- File `PlayerKits2/kits/cipiprime.yml` dan `cipi++.yml` yang diberikan Owner memakai `permission_required: true`, `cooldown: 18000` (5 jam), tanpa `custom_permission` atau `requirements` tingkat utama pada file yang diberikan. `ELITE` terlihat pada lore/tampilan `no_permission`, bukan aturan rank dalam file tersebut. Konfigurasi yang sedang dimuat dan klaim sebenarnya masih harus diuji; syarat di tempat lain tidak dapat dikesampingkan.
- Dokumentasi PlayerKits2 menjelaskan default `playerkits.kit.<kit>` (singular) ketika permission diperlukan: https://ajneb97.gitbook.io/playerkits-2/kits-tutorial. Dua kandidat khusus adalah `playerkits.kit.cipiprime` dan `playerkits.kit.cipi++`. Tes di server nyata belum membuktikan grant, klaim, isi, cooldown atau revoke.
- Percobaan comp Cipi++ produksi sebelumnya mencatat `DELIVERED`, namun memasang `playerkits.kits.cipi++` (plural, tidak sesuai default) dan menu tetap terkunci. Pada pemeriksaan LuckPerms akun uji, node singular `playerkits.kit.cipi++` adalah `undefined`. Entitlement comp dan permission plural lama tetap ada. Jangan retry/comp/cabut otomatis; cocokkan UUID, konteks, log dan hak nyata sebelum menentukan tindakan manual.
- Pada akun tes, `essentials.kits.cipi++` bernilai true melalui `essentials.kits.*` pada grup default. Ini berpotensi memberi akses ke kit Essentials lain, namun efek nyata bergantung pada kit dan izin/command yang tersedia. Menambah atau unset node langsung tidak menghilangkan warisan wildcard. Audit terpisah untuk seluruh pemain dan sumber permission; **jangan otomatis cabut wildcard**.
- Staging menjalankan PR #8 dan migrasi 0021: template kedua kit memakai Essentials dan teksnya menyebut Essentials, meskipun menu yang ditemukan memakai PlayerKits2. Ada dua delivery Sandbox `QUEUED` untuk produk lain. Worker staging berhenti, checkout ditutup, endpoint plugin 503 pada pemeriksaan terakhir. Jangan sambungkan staging ke Minecraft produksi dan jangan mengaktifkan antrean untuk mencoba perubahan ini.

## Kode, migrasi, dan risiko

- Allowlist website dan companion baru hanya menerima dua node singular PlayerKits2 di atas untuk set true/unset, serta grup rank yang telah ditentukan. Essentials, plural lama, wildcard, kit lain, target berbeda dan perintah arbitrer ditolak. Website dan companion harus dirilis bersama, dengan polling tertutup saat pergantian.
- Migrasi historis **0021 tidak diubah**. Migrasi 0022 hanya mengubah pasangan GRANT/REVOKE bawaan yang persis sama dari Essentials atau plural lama menjadi singular `{uuid}`, bila produk tidak memiliki **riwayat entitlement atau delivery apa pun**. Template kustom, campuran, duplikat, dan produk bersejarah ditahan. Pada database yang belum menerapkan 0021, migrasi berjalan berurutan: 0021 kemudian 0022. Teks default Essentials yang cocok persis diperbarui secara independen, termasuk pada produk yang templatenya ditahan; ini bukan bukti pengiriman bekerja.
- Migrasi tidak mengubah entitlement, delivery, perintah tersimpan, antrean plugin, marker, atau LuckPerms. Pengiriman Essentials/plural lama akan ditolak oleh pengaman baru, berpotensi menjadi DEAD jika polling dibuka. Produk produksi Cipi++ yang memiliki riwayat comp tetap memerlukan tindakan manual. Tidak ada retry, pemberian, pencabutan atau transfer hak otomatis.
- REVOKE mengambil template produk saat dibuat. Mengubah template pada produk bersejarah dapat mencabut izin yang diperoleh dari sumber lain atau gagal mencabut izin lama; unset juga tidak meniadakan izin warisan. Review per pemain, konteks, sumber dan tanggal hak sebelum menentukan rencana tindakan. Seed melewati produk yang sudah ada; jangan menghapus produk untuk memaksa seed.
- Snapshot opsional berasal dari PlayerKits2 dan belum divalidasi pada runtime tersebut; teks terlokalisasi bukan hitung mundur atau bukti kelayakan klaim. Biarkan `live-status.enabled=false` sampai diuji.

## Rencana aman

1. Tetap tutup checkout dan endpoint plugin, matikan polling, dan pastikan worker staging tetap berhenti. Compose staging memiliki `name: cipismp-store`: gunakan `-p cipismp-staging` hanya setelah memverifikasi project, env, jaringan, port dan volume; ini saja tidak membuktikan isolasi. Jangan arahkan website/worker/plugin staging ke Minecraft produksi.
2. Buat backup terbaru database, konfigurasi dan data LuckPerms/antrean plugin; uji restore secara terisolasi. Backup lama tidak mencakup perubahan sesudahnya, dan restore bukan rollback otomatis. Catat image versi lama dan uji rencana rollback tanpa menebak status pembayaran/permission.
3. Uji migrasi lengkap 0021→0022 pada salinan database terisolasi, termasuk template lama/kustom, riwayat, grant/revoke, antrean dan copy. Audit seluruh delivery, entitlements, lease, marker, identitas dan efek Minecraft; rekonsiliasi manual kasus ambigu bersama Owner.
4. Pada Minecraft staging yang benar-benar terpisah: gunakan build website dan companion yang cocok, periksa file kit yang dimuat, permission efektif termasuk wildcard/contexts, dan uji grant, klaim menu, isi kit, cooldown, revoke, Java/Bedrock, offline, ACK hilang dan restart/crash. Jangan menganggap hanya `DELIVERED`, snapshot atau kompilasi sebagai bukti akses. Pastikan teks Cipi++ tidak menjanjikan semua tools netherite: file kit menunjukkan axe dan shovel diamond.
5. Setelah security review dan bukti staging, minta persetujuan Owner untuk rencana rollout serta setiap tes produksi terbatas. Checkout dan polling tidak otomatis dibuka. Jika tidak ada server Minecraft staging, jangan hubungkan staging ke produksi; tentukan alternatif dan risiko bersama Owner sebelum tindakan.
